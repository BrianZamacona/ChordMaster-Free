# 🎸 ChordMaster Free

[![CI](https://github.com/BrianZamacona/ChordMaster-Free/actions/workflows/ci.yml/badge.svg)](https://github.com/BrianZamacona/ChordMaster-Free/actions/workflows/ci.yml)

> **Free, offline-first music learning app for guitarists, pianists and musicians of all levels.**  
> No subscription. No internet required. Just music.

---

## ✨ Features

| # | Module | Description |
|---|--------|-------------|
| 1 | 🎸 **Chord Library** | 288 guitar chords (24 types × 12 roots) with fingerings, CAGED positions, voicings and inversions, all validated note by note |
| 2 | 🎵 **Scale Explorer** | 12 scales and 7 modes in 4 fingering systems (CAGED, 3NPS, Pentatonic Box, Linear 4NPS) for any root, plus diatonic double stops with per-string-pair diagrams |
| 3 | 🎙️ **Guitar Tuner** | Chromatic tuner using the device microphone with cents deviation display |
| 4 | 🥁 **Metronome** | Precision metronome with tap-tempo, subdivision and custom time signatures |
| 5 | 🔗 **Chord Progressions** | 9 classic progressions in any key, with the smoothest voice-leading path of real fingerings and a transition indicator between chords |
| 6 | 👂 **Ear Training** | Interval, chord and melody recognition exercises with adaptive difficulty |
| 7 | 🎮 **Rhythm Game** | Tap-along rhythm challenges that improve your internal pulse and timing |
| 8 | 🎼 **Improvisation** | Backing tracks with scale overlays to guide freestyle soloing practice |
| 9 | 📚 **Song Library** | Offline song catalog with chord sheets, tabs and play-along mode |
| 10 | 🎹 **Composition Studio** | Multi-track MIDI-style composer for sketching original song ideas |
| 11 | 💆 **Health & Wellness** | Warm-up routines, hand stretches and practice session timers |
| 12 | 📋 **Community Board** | Local bulletin board for saving tips, links and shared resources |
| 13 | 🏆 **Achievements** | Gamified progress tracking with streaks, badges and XP milestones |
| 14 | ⚙️ **Settings** | Theme customisation, instrument selection and notification preferences |

## 🏛️ Architecture

Music theory lives in a pure-Dart **domain layer** (no Flutter imports) that the screens consume:

```
lib/
├── domain/        # Pure Dart: double stops, ergonomics, voice leading,
│                  #   progressions, fingering-system theory
├── data/          # Scale models and repository (resolves positions per root)
├── models/        # Chord, progression, song... models
├── features/      # One folder per module (screen + view-model)
├── ui/            # Router, theme, scale screens, double-stops screen
├── core/          # Constants, i18n, shared widgets, utils
└── services/      # Audio, storage (Hive), notifications, pitch detection
```

**Key design decisions:**
- **One source of truth per musical topic, generated by rules and audited.** Chord
  fingerings (`assets/data/chords.json`) and scale positions (`assets/data/scales_master.json`)
  are produced by scripts in `tool/` and checked by audits and tests that require every
  played note to belong to the chord or scale (zero tolerance).
- Domain engines (ergonomics, voice leading, double stops) are verified against reference
  results exported from a TypeScript prototype (`test/fixtures/golden/`).
- State is managed with **Riverpod**; navigation with **GoRouter**; persistence with **Hive**.
- See [`CLAUDE.md`](CLAUDE.md) for conventions, data pipelines and the contribution workflow.

## 🌍 Localization Strategy

- Runtime model: **static localization files** with offline-first fallback.
- Gold locales: **English (en)** and **Spanish (es)**.
- Additional rollout locales: **pt, de, ru, zh, ja, fr, it** (machine-assisted + human review workflow).
- No runtime auto-translation API in production (cost, quality and offline constraints).

## 🚀 Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/BrianZamacona/ChordMaster-Free.git
cd ChordMaster-Free

# 2. Install dependencies
flutter pub get

# 3. Launch on a connected device or emulator
flutter run
```

> **Requirements:** Flutter SDK ≥ 3.41.5, Dart SDK ≥ 3.11.0, JDK 21 (LTS) for Android builds

## 📁 Project Structure

```
lib/
├── domain/
│   ├── theory/double_stops.dart        # Diatonic double stops
│   ├── voicing/                        # Ergonomics, voice leading, adapter
│   ├── progressions/                   # Progression data and builder
│   └── fingering_systems/              # Theory + registry of fingering systems
├── data/                               # Scale models and repository
├── features/                           # chords, progressions, tuner, metronome,
│                                       # ear_training, rhythm_games, improvisation,
│                                       # songs, composition, health, community,
│                                       # achievements, settings, home
├── ui/scales/                          # Scale list/detail and double stops
└── main.dart

assets/
├── audio/   ├── data/ (chords.json, scales_master.json, ...)   └── images/

tool/                                   # Data generators and audits (Python)
test/                                   # core, data, domain, features, models, widget
                                        # + fixtures/golden (reference results)
```

## 🧪 Running Tests

```bash
# Run all tests
flutter test

# Run with coverage
flutter test --coverage
genhtml coverage/lcov.info -o coverage/html

# Run a specific test file
flutter test test/domain/progression_builder_test.dart

# Run widget tests only
flutter test test/widget/

# Audit the music data (must report 0 defects)
python tool/audit_chord_music.py assets/data/chords.json
python tool/audit_scales_master.py
```

## 🔄 CI / CD

| Trigger | Workflow | Action |
|---------|----------|--------|
| Push / PR → `main`, `develop` | `ci.yml` | Lint + analyse + full test suite |
| Push tag `v*` (e.g. `v1.2.0`) | `release.yml` | Build release APK, upload as artifact |

Releases are created by tagging the commit:

```bash
git tag v1.0.0 && git push origin v1.0.0
```

The release APK is available under **Actions → Release APK → Artifacts**.
